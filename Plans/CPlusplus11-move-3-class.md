## 3. コード例

すべて `main.cpp` に置き、`main` から順に呼ぶ。題材は「`int` の配列をヒープ上に持つクラス `Buffer`」で統一する。コピーコンストラクターとムーブコンストラクターは、呼ばれたときにメッセージを出す。

| 例 | キャプション案 | 内容 |
|---|---|---|
| 例 1. | 「コピーしかできないクラスは、一時オブジェクトからもコピーする」 | Rule of Three だけの `Buffer` を、関数の戻り値や `std::move` で別の変数に渡す。いずれもコピーになることを出力で示す |
| 例 2. | 「ムーブコンストラクターとムーブ代入演算子を書く」 | `Buffer(Buffer&& other) noexcept` と `Buffer& operator=(Buffer&& other) noexcept` を足す。ポインターを引き取り、ムーブ元を `nullptr` と 0 にする |
| 例 3. | 「ムーブできるクラスは、一時オブジェクトからムーブする」 | 例 1 と同じ呼び出しで、出力がムーブに変わることを示す |
| 例 4. | 「`noexcept` がないと、`std::vector` の再確保でコピーされる」 | ムーブコンストラクターに `noexcept` がある型とない型を用意する。それぞれ `reserve(2)` で容量を2にしてから3個追加し、3個目で再確保が1回だけ起きるようにする。再確保で既存の2個が、前者はムーブ、後者はコピーされることを出力で示す |
| 例 5. | 「リソースを標準ライブラリに任せれば、ムーブを書かずに済む」 | `Buffer` の代わりに `std::vector<int>` をメンバーに持つクラスを書く。コピー・ムーブ・デストラクターを書かなくても、ムーブできることを示す |

- 例 2・例 3 が、この記事の要。
- 例 4 では、`reserve` で容量を決めて、再確保の回数が実装の容量の増やし方に左右されないようにする(連載全体の計画書 4節)。`push_back` に渡す一時オブジェクト自体のムーブも出力に出るので、再確保によるものと区別できるよう、出力の前後に区切りを出すか、`emplace_back` を使わずに組み立てる方法を実装時に決める。
- 例 4 で使う二つの型は、ログを出すだけの小さな型にする(配列を持たない)。`noexcept` の有無だけが違うことを、コードで見比べられるようにする。
- 例 5 で、ムーブできたことを示す方法(`data()` の比較など)は、記事 2 の例 1 に合わせる。
- コピー代入演算子は、copy-and-swap にするか、素直に書くかを実装時に決める。記事の要点から外れるので、記事には埋め込まず、「省略」と書いて `Sources/` にだけ置くことも検討する。
- 注意点の「デストラクターを宣言すると、ムーブが自動で作られない」は、コード例にするか地の文にするかを、分量を見て決める。

## 4. 扱わないこと

- 右辺値参照の考え方(記事 1)。この記事では、「`T&&` は右辺値だけを受け取る参照」と1文で述べ、記事 1 へのリンクを添える(連載全体の計画書 7節)
- 完全転送(記事 4)
- `std::move_if_noexcept` の詳細。`std::vector` の再確保の動きを説明するときに、名前を出す程度にする
- `std::exchange` (C++14)。ムーブコンストラクターを短く書けるが、C++11 にはない。触れる場合は、C++14 の機能だと明記する
- `std::unique_ptr` にカスタムデリーターを指定して、リソースを管理する方法
