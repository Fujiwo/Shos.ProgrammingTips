## 3. コード例

すべて `main.cpp` に置き、`main` から順に呼ぶ。題材は「`int` の配列をヒープ上に持つクラス `Buffer`」で統一する。コピーコンストラクターとムーブコンストラクターは、呼ばれたときにメッセージを出す。

| 例 | キャプション案 | 内容 |
|---|---|---|
| 例 1. | 「ムーブ操作がないクラスは、右辺値からもコピーする」 | Rule of Three だけの `Buffer` の変数を `std::move` で別の変数の初期化に使い、コピーになることを出力で示す。関数の戻り値はコピー省略で出力が変わるため、比較には使わない |
| 例 2. | 「ムーブコンストラクターとムーブ代入演算子を書く」 | `Buffer(Buffer&& other) noexcept` と `Buffer& operator=(Buffer&& other) noexcept` を足す。ポインターを引き取り、ムーブ元を `nullptr` と 0 にする |
| 例 3. | 「ムーブ操作を持つクラスは、右辺値からムーブする」 | 例 1 と同じ呼び出しで、出力がムーブに変わることを示す。構築済みの別の変数へのムーブ代入と自己ムーブ代入も確認する |
| 例 4. | 「コピー可能な型の再確保で、`noexcept` の有無を比べる」 | コピー可能で、ムーブコンストラクターに `noexcept` がある型とない型を用意する。それぞれ要素を2個準備した後に `reserve(v.capacity() + 1)` を呼び、再確保を確実に起こす。その呼び出し中に既存の2個が、前者はムーブ、後者はコピーされることを、確認対象の実装で出力して確かめる |

- 例 2・例 3 が、この記事の要。
- 例 4 では、要素の準備と `reserve(v.capacity() + 1)` の前後に区切りを出し、再確保による出力を準備中の出力と分ける。`reserve` の要求値が現在の容量を超えるので、この呼び出しでの再確保は実装の容量の増やし方に左右されない(連載全体の計画書 4節)。
- 例 4 で使う二つの型は、コピー可能でログを出すだけの小さな型にする(配列を持たない)。`noexcept` の有無だけが違うことを、コードで見比べられるようにする。
- Rule of Zero は独立したコード例にせず、2節の補足にとどめる。本文は `Buffer` のムーブ操作の実装と使い方を優先する。
- コピー代入演算子は、copy-and-swap にするか、素直に書くかを実装時に決める。記事の要点から外れるので、記事には埋め込まず、「省略」と書いて `Sources/` にだけ置くことも検討する。
- 注意点の「デストラクターを宣言すると、ムーブが自動で作られない」は、コード例にするか地の文にするかを、分量を見て決める。

## 4. 扱わないこと

- 右辺値参照の考え方(記事 1)。この記事では、「`T&&` は右辺値だけを受け取る参照」と1文で述べ、記事 1 へのリンクを添える(連載全体の計画書 7節)
- 完全転送(記事 4)
- `std::move_if_noexcept` の詳細。`std::vector` の再確保の動きを説明するときに、名前を出す程度にする
- `std::exchange` (C++14)。ムーブコンストラクターを短く書けるが、C++11 にはない。触れる場合は、C++14 の機能だと明記する
- `std::unique_ptr` にカスタムデリーターを指定して、リソースを管理する方法
