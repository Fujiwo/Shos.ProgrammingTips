### 1-1. タイトル

案は次のとおり。

- 案1: `C++11 の完全転送: 受け取った引数を、左辺値か右辺値かを保ったまま渡す`
- 案2: `C++11 の完全転送: 引数を中継する関数で、ムーブを途切れさせない`
- 案3: `C++11 の転送参照と std::forward: オーバーロードを増やさずに、引数をそのまま渡す`

案1を推奨する。完全転送が何をする機能かを、そのまま示せる。

| 節 | 内容 | 4点との対応 |
|---|---|---|
| 導入 | 「完全転送を紹介します」で始め、利点(引数を別の関数に中継するとき、左辺値か右辺値かと `const` の有無を保ち、適切なオーバーロードを選べる)を短く述べる。前提 | |
| これまでの書き方と課題 | 引数を受け取って、別の関数やコンストラクターに渡すだけの関数(ファクトリー関数など)を書く。`const T&` で受けると、右辺値を渡してもコピーになる。`const T&` と `T&&` のオーバーロードを両方書くと、引数が n 個なら 2 の n 乗通りになる | |
| 完全転送とは | 受け取った引数を、左辺値か右辺値か(と `const` かどうか)を保ったまま、別の関数に渡すこと。転送参照と `std::forward` を組み合わせて実現する | 意味 |
| 転送参照 | テンプレートの引数で型推論される `T&&` は、右辺値参照ではなく転送参照になり、左辺値にも右辺値にも束縛できる。左辺値を渡すと `T` は `U&` に、右辺値を渡すと `T` は `U` に推論される。`U& &&` のような参照の参照は、参照の折りたたみの規則で `U&` になる。推論の結果を表で示す(2-1) | 意味・書き方 |
| `std::forward` の書き方 | `std::forward<T>(arg)` は、`T` が左辺値参照なら左辺値として、そうでなければ右辺値として `arg` を渡す。`std::move` が常に右辺値にするのに対し、`std::forward` は条件付きで右辺値にする。どちらもキャストであり、それ自体はムーブしない。実際にムーブするかは、転送先の処理による | 書き方 |
| 完全転送を使うメリット | オーバーロードを一つにまとめられる。中継する関数を挟んでも、ムーブが途切れない。標準ライブラリの `emplace_back` や `std::make_shared` は、この仕組みで、要素のコンストラクターに引数を渡している | メリット |
| 使うときの注意点 | `T&&` がいつも転送参照になるわけではない。型推論されないとき(`std::vector<T>` のメンバー関数 `push_back(T&&)` など)や、`const T&&` は右辺値参照。転送先がムーブなどで引数の中身を引き取る場合は、同じ引数を複数回転送しない。1回目の処理でムーブされると、2回目にはムーブ後の値が渡るため。転送参照を取る関数は何にでも合うので、ほかのオーバーロードより優先されやすい | |
| まとめ | 3点程度の箇条書き | |

### 2-1. 型推論の表(案)

`template <typename T> void Relay(T&& arg)` を呼んだときの推論結果。

| 渡す値 | `T` の推論結果 | `arg` の型 | `std::forward<T>(arg)` |
|---|---|---|---|
| `std::string` の変数(左辺値) | `std::string&` | `std::string&` | 左辺値 |
| `const std::string` の変数(左辺値) | `const std::string&` | `const std::string&` | 左辺値 |
| `std::string` の一時オブジェクト(右辺値) | `std::string` | `std::string&&` | 右辺値 |

## 3. コード例

すべて `main.cpp` に置き、`main` から順に呼ぶ。題材は「名前を受け取るクラス `Widget` を作るファクトリー関数」で統一する。`Widget` のコンストラクターは `const std::string&` と `std::string&&` のオーバーロードを持ち、どちらが呼ばれたか(コピーかムーブか)を出力する。

| 例 | キャプション案 | 内容 |
|---|---|---|
| 例 1. | 「`const` 参照で中継すると、右辺値もコピーになる」 | `template <typename T> T Create(const std::string& name)` で `Widget` を作る。一時オブジェクトを渡しても、`Widget` ではコピーのコンストラクターが呼ばれることを示す |
| 例 2. | 「転送参照と `std::forward` で、引数をそのまま渡す」 | `template <typename T, typename Arg> T Create(Arg&& arg)` の中で `T(std::forward<Arg>(arg))` とする。変数を渡すとコピー、一時オブジェクトや `std::move` を渡すとムーブになることを示す |
| 例 3. | 「`std::forward` を書き忘れると、ムーブが途切れる」 | 例 2 から `std::forward` を外すと、右辺値を渡してもコピーになることを示す。記事 1 の「名前の付いた右辺値参照は左辺値」の応用 |
| 例 4. | 「可変長の引数を、まとめて転送する」 | `template <typename T, typename... Args> std::unique_ptr<T> MakeUnique(Args&&... args)` で、`new T(std::forward<Args>(args)...)` とする。`emplace_back` や C++14 の `std::make_unique` と同じ形であることを述べる |

- 例 2 が、この記事の要。例 1 と同じ呼び出しで、出力だけが変わることを見せる。
- 例 4 は可変引数テンプレート (C++11) を使う。可変引数テンプレートは別の機能なので、「引数の個数を問わないテンプレート」と一言で説明するにとどめる。分量が目安を超える場合は、例 4 を外し、`emplace_back` が完全転送を使っていることを地の文で述べるだけにする。
- `MakeUnique` という名前は、C++14 の `std::make_unique` と同じ働きをする自作の関数であることを、コメントと地の文で明記する。
- 例 3 は、例 2 との違いを1行だけにして、見比べやすくする。

## 4. 扱わないこと

- 右辺値参照の考え方と `std::move` の正体(記事 1)。この記事では、記事 1 の要点を1〜2文で述べ、リンクを添える(連載全体の計画書 7節)
- `auto&&` が転送参照になること。注意点で1文触れる程度にする
- 可変引数テンプレートの詳細(パラメーターパックの展開の規則など)
- `decltype` を使った戻り値の型の推論
- 転送参照を取る関数のオーバーロードを、SFINAE や `enable_if` で制限する方法
- C++20 の `auto` を使った省略形の関数テンプレート
