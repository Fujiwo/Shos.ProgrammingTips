### 1-1. タイトル

`C++11 の auto: 長い型名を書かずに、型を正しく受ける`(8節で決定)

「書く量が減る」だけでなく「型の書き間違いを防ぐ」というメリットまで、タイトルで示せる。

検討したほかの案は次のとおり。

- `C++11 の auto で、イテレーターの型名から解放される`

### 1-2. 冒頭に書く前提

- 対象: C++11 以降
- 開発環境: Visual Studio 2026 (MSVC v145)。MSVC には `/std:c++11` がないため、`/std:c++14` でビルドする。使う機能は C++11 の範囲に限る

## 3. コード例

すべて `CPlusplus11Auto/main.cpp` に、例ごとの関数として置き、`main` から順に呼ぶ。記事には各関数の本体を埋め込む。

| 例 | キャプション案 | 内容 |
|---|---|---|
| 例 1. | 「C++03 までのイテレーターの書き方」 | `std::map<std::string, std::vector<int>>::const_iterator it = scores.find("Alice");` のように長い型名を書く |
| 例 2. | 「`auto` でイテレーターを受ける」 | 例 1 を `auto it = scores.find("Alice");` に書き換える |
| 例 3. | 「型の書き間違いで、気付かずにコピーが作られる」 | `std::map<std::string, int>` の要素を `const std::pair<std::string, int>&` で受けると、本来の `std::pair<const std::string, int>` と型が違うため一時オブジェクトが作られる。アドレスを比べて、別のオブジェクトであることを出力で示す |
| 例 4. | 「`const auto&` なら、要素そのものを参照できる」 | 例 3 を `const auto&` に書き換え、アドレスが一致することを示す |
| 例 5. | 「`auto` は参照を落とす」 | `auto value = scores["Alice"]; value += 10;` ではマップの値が変わらない。`auto&` なら変わる |

- 例 3・例 4 が、この記事の要。「書く量が減る」だけでなく「正しい型を受けられる」ことを見せる。
- 範囲 for 文 (C++11) は連載の別の記事で扱うため、ここでは使わない。イテレーターと `find` で書く。
- 本文に載せる出力は、実行結果と一致させる。
- データの準備(波括弧による初期化も C++11 の機能)は `MakeScoreHistory`・`MakeLatestScores` に分け、記事に埋め込む部分を `auto` の話だけにする。
- 出力は英語にする。日本語を出力すると、Windows のコンソールの文字化け対策のコードが要り、要点がぼやけるため。コメントは日本語。

## 4. 扱わないこと

この記事は一つの機能に絞るため、次は扱わない。必要なら `※` の注記で触れる程度にする。

- `decltype` と後置戻り値型 (`auto f() -> decltype(...)`)
- 関数の戻り値型の推論(C++14)、ジェネリックラムダ(C++14)、構造化束縛(C++17)。後続の連載で扱う
- `auto x{1};` の推論結果(C++17 で規則が変わった、N3922)。混乱を招くので、本文では触れないか注記にとどめる
- ラムダ式を `auto` で受ける書き方。ラムダ式の記事で扱う
- 「Almost Always Auto」の是非。注意点の節で、使いどころの目安として一言触れる程度にする
